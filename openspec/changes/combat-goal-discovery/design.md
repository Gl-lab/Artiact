# Design

CombatDiscovery is legal only with AutonomousGoals. AllowFight, AllowEquip, AllowCraft, AllowBankWithdrawal default false. Rest/use are governed by optional Recovery (needed at any HP deficit for a combat prerequisite, independent of its standalone threshold). MaxMaterialUnits defaults 100; Reserved stock floors default empty. Bank withdrawal requires BankRetain. Gear craft inputs charge combat:materials globally, conservatively at intent. Recovery retains its own global limits. Catalog limits: 4096 monsters, 16384 items, 10 ordinal supported opponent alternatives and 20 ordinal supported weapon/shield replacements. No combined loadout search or loot-only economic goals.

combat-discovery-v1 generates the next observed combat level up to cap50. A current safe opponent grants progress utility0.1. A supported replacement that makes an otherwise unsafe opponent safe grants unlock utility1; an improvement of an already safe fight keeps only progress0.1. There is no separate item/ingredient utility. Equipment must be usable at the current level. This prioritizes opening a usable combat route while R10 cost includes finite stock, crafting, training, travel, equip, fights and recovery. All alternatives target the same next level; persist one combat parent and re-evaluate its routes after every observation. Completion reads character level (not combat_level). No useful terminal needs the combat cap as well when discovery is enabled.

R9 handles projection, prerequisite planning and verified commands; generated policies never broaden user permissions. Select a supported safe effect-free loot fallback automatically for preparation. Refuse gear paths needing disallowed crafting, absent inventory/bank supply or unsafe/unsupported loot. Conservatively reserve stock and charge all dispatched craft inputs, including training. Filter forbidden next commands and reject full estimated material paths before starting. Fight/rest/gear/production candidates share original source fingerprint and pending baseline.

For injured combat paths, use the existing finite recovery discovery with threshold100 as a prerequisite of the combat parent. Compare allowed rest and heal-only foods without rewarding HP separately; parent XP alone is productive. Recovery policy remains the user's source of permissions and allowances. If no allowed recovery route exists, exclude the combat route before any fight. Recovery supply cost is added to the combat path. Existing training/cooldown estimates remain explicitly uncertain.

Version-2 history accepts combat-discovery-v1 with Skill=combat, Target2..50, utility1 or progress0.1. Catalog changes reject active parents; suppressed rejected targets, pending replay, history/budget bounds and terminal archive keep existing rules. Absent CombatDiscovery does not change manual/R11–R13 identity or required schemas. Only enabled combat permissions add their schema probes.

Implementation clarification: a selected route-opening parent retains its opponent and utility after healing/equipping. Recomputing the initial opening utility from the already improved state would erase the purpose mid-chain. The initial score/formula and preregistered scenario/ceilings are unchanged.

Official combat/XP/cap50 page inspected 2026-09-08: https://docs.artifactsmmo.com/concepts/stats_and_fights . R9 arithmetic remains the local supported model; no live proof is inferred.
