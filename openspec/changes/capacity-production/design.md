# Design

Add an optional Production policy, omitted from serialized identity when absent. `Reserved` is an ordinal quantity floor across inventory plus bank. Add the existing quantities of other final item goals to the planning reservation view. The allocator subtracts reserved stock from planning availability, never from actual observations or command postconditions. Fresh one-command execution prevents simultaneous allocation of the same actual ingredient.

Plan one additional root output batch at a time and limit intermediate craft steps to one recipe execution. Already bank-owned final products reduce the outstanding order and are excluded from top-level withdrawal needs. Recompute after every command. Preserve complete-world fingerprints and compare exact real stock transitions.

Under pressure, derive a temporary deposit retain policy from the explicit bank allowlist, protected inventory, other final quotas and one batch of the nearest upcoming craft's ingredients. If no allowed excess exists, block. A minimal recipe exceeding capacity after protected stock is excluded must block before an unproductive bank route. Deposits retain their existing full-bank/access/conservation guards and do not reset the parent's productive progress counter.

Use independent synthetic `capacity-production` and constrained R7 scenarios; the mock remains scripted and uses the existing array bank and craft contracts. The default production path remains unchanged when the policy is absent.
