# Design

Public sources read without credentials on 2026-09-07: [rest/use rules](https://docs.artifactsmmo.com/concepts/resting_and_using_items), [OpenAPI](https://api.artifactsmmo.com/openapi.json), and `/items/cooked_gudgeon`. Cooked gudgeon is an unconditional consumable with heal=75 and a cooking-1 recipe consuming one gudgeon. OpenAPI use takes SimpleItemSchema and returns UseItemSchema containing full ItemSchema, character and cooldown. Cooking/fishing level/XP/max-XP fields are present. This verifies the public subset, not a live use.

One optional consumable policy names its parent item candidate, code, HP threshold, minimum/target/reserve, maximum used quantity and material units, optional-rest rule and estimates. The first effect path requires exactly one positive heal effect and empty conditions. HP is capped at max HP. Use a useful bounded quantity and exact stock conservation; bank state must remain unchanged. Verify the returned item definition and cooldown envelope before recording success.

Add optional per-command resource charges and refill markers to the durable journal. Charge before POST; rejected/unknown attempts do not refund allowance. Reconstruct a read-only run context from the journal for evaluation and saved-baseline command reconstruction. Run context does not replace server-state fingerprints. A refill trigger remains active until target stock is reached, even after crossing the minimum; a subsequent use/parent command clears the phase. Every supply command stays associated with the parent and shares its global action/time/no-progress budget. Refill production alone must not repeatedly erase the parent's no-progress accounting.

The wrapper first checks parent completion. It supplies a batch when below minimum or refilling, withdraws only the needed usable inventory, then heals if policy requires it. Optional rest uses missing-HP percentage time versus estimated use/preparation cost. Reserve is a conserved quantity across inventory plus bank. Existing item quantity goals stay independent. Extend R7's explicitly verified profession subset to cooking/fishing, with authored scenarios and API probes; do not infer every profession is supported.
