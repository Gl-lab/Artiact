# Design

Use an in-process portfolio, not a persistent workflow engine. Each strategy owns candidate generation and its command/postcondition. The coordinator has no goal-type switch. Gathering takes a profession descriptor, allowing mining and woodcutting without coordinator changes. Combat reuses the supported normalization, predictor and map/equipment rules from Epic 6.

An observation owns cloned JSON character/catalog data plus policy identity. Canonical JSON object ordering produces a SHA-256 fingerprint; array order is preserved conservatively. Every tick observes again. Immediately before dispatch it observes once more; any difference yields Replan with zero POSTs. A command is single use within a session. Successful postconditions consume it; later ticks plan from new state rather than replaying a command list.

Candidate utility is configured useful progress divided by estimated complete-cycle seconds (productive action, travel and recovery), with deterministic ordinal ID ties. Hard constraints reject before scoring. Scores expose components and rejection reasons; estimates are explicit policy inputs, not claims about live optimality. Invalid configuration and duplicate candidate IDs block.

Unknown dispatch outcomes retain the pending command and attempt budget. The next tick only refreshes and evaluates its postcondition. A satisfied postcondition yields Reconciled; an unchanged or ambiguous snapshot remains UnknownOutcome and stops further mutation. This is evidence of desired state, not proof of causation. Rejected commands stop. Cancellation before dispatch issues no POST; cancellation after a response retains state and cannot replay. Session-wide decision and no-progress limits bound repeated replans and recovery.

Catalogs are fresh reads for the new path; Epic 8 adds bounded freshness/version status. External mutation between preflight and POST cannot be made atomic without server support. No automatic retry can eliminate that race. Legacy paths remain tested compatibility entry points; the new portfolio is explicit and not silently made autonomous.

## Review clarifications and independent oracle
Postconditions compare with captured pre-dispatch state: movement changes to the requested map without identity/layer change; gather/fight advances the intended skill/level and preserves valid inventory/HP; equipment changes the exact slot and conserves the exact inventory delta. A lost response cannot prove causation, only that this baseline-relative desired transition is now present. No change, unrelated change, invalid state or catalog change is terminal UnknownOutcome. Reconciled consumes the command without refund, allows planning only on a later tick, and observes remaining cooldown before any later mutation. A future cooldown expiration produces CoolingDown with no action. Cancellation after reply retains the new observation before terminal Cancelled. Defeat and invalid postconditions stop. All goals complete means Completed; any unfinished but infeasible goals mean Blocked if no candidate is feasible.

Every nonterminal tick charges one decision, including stale preflight and reconciliation; every attempted command/stale tick charges no-progress. Productive verified progress resets no-progress; movement and recovery do not. Inspect does not charge a dispatch. Limits are positive and exhaustion never refunds a command.

Named `strategy-portfolio` HTTP scenario starts with the independently specified combat-equipment character (level 1, HP 20, map 1, old equipped, quick_blade and heavy_blade each 1, capacity 10); mining and woodcutting both level 1/XP 0. Mine map 4 gives ore 1 and skill XP 5 in 5 seconds; forest map 5 gives wood 1 and skill XP 5 in 5 seconds. Each skill target is 2 with threshold 10. Combat target 2 uses dummy; equipment target quick_blade. Estimates: move 7, gather 5, fight 8, recovery 6, each equipment action 3. Values equipment 100, mining 30, woodcutting 20, combat 10. Complete-cycle scores initially equipment 100/6, mining 30/12, woodcutting 20/12, combat 10/21. Equipment, skill and combat are simultaneously feasible; value variants make each category win. Equal scores use ordinal candidate IDs; invalid estimates reject configuration.

Expected actions: Unequip, Equip, Move(4), Gather, Gather, Move(5), Gather, Gather, Move(2), Fight, Rest, Fight, then Completed. Twelve actions, thirteen decisions, 69 seconds; final all three levels 2/XP 0, HP 14, map 2, quick_blade equipped; heavy_blade, old each 1, ore, wood, feather each 2, free units 2. Every complete response and replayed decision/trace/state is independently checked. Existing combat and crafting response oracles remain unchanged.
