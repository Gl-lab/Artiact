# R15: Autonomous quality and operational acceptance

Consolidate the R11–R14 preregistered quality matrix and extend it with long runs, near-full inventory and inaccessible routes. Keep useful outcomes separate from cost and skill-specific XP. Verify budgets, stock, changed catalogs, uncertain results and process restart; publish wins, ties, failed outcomes and retained implementation failures.

Affected scope: deterministic mock/tests, dated evidence and operational/live protocol documentation; production changes only if a behavioral failure is demonstrated. No current live action authorization is inferred. A bounded live acceptance protocol will be delivered separately; combat remains prohibited by ADR0001.

Acceptance requires the accumulated matrix plus new scenarios, zero default cost regression for equivalent useful outcomes, at least one measured command win without cooldown growth, exact durable invariants and solution tests. A published matrix alone is insufficient. Preserve the R12/R13 intermittent reopen limitation unless diagnosed.
