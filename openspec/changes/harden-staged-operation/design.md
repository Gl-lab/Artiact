# Design

## Transport
Token acquisition is serialized and uses a request-local Basic header; every other request uses request-local Bearer. Schedule refresh from a readable JWT expiry when present (only a scheduling hint, never signature validation); opaque tokens refresh on 401. GET may repeat once after token refresh or transient 429/5xx/network failure, with bounded Retry-After handling. POST dispatches once: 401 invalidates the token for a later explicit operation but never repeats the action. Token rejection/malformed token fails before action dispatch. Production handler disables redirects and bounds request timeout. No credential/body logging.

## Observation and cache
New portfolio observations continue reading raw catalogs. A compatibility probe checks configured expected OpenAPI version and the used route/schema subset; status exposes drift instead of claiming full OpenAPI equivalence. An observation whose collection took longer than the configured freshness interval is rejected before planning. Health records last successful probe/observation time and expires readiness; health endpoints never call the game API. Legacy file cache moves to application-local storage with endpoint/version identity, format version, UTC creation time, TTL, atomic replacement and corrupt-file miss behavior. Tracked snapshots remain untouched.

## Staged host
`Execution:Mode` is Inspect by default. Inspect evaluates candidates and emits a sanitized decision without executing command delegates. OneShot runs one portfolio tick and, for an unknown outcome, at most one read-only reconciliation tick. It never runs a second mutation. Explicit `Execution:AllowActions` is required for OneShot/Legacy; non-loopback destinations additionally require `Execution:LiveActionsApproved`. Only loopback HTTP or the official HTTPS API origin is accepted by staged settings; credentials may not be redirected. The legacy entry point is preserved but not claimed live-safe. Missing configuration yields a visible failed readiness state without dispatch.

Liveness means the web process can answer; readiness means initialized, compatible, fresh, and no blocked/unknown/failed worker state. Completed/inspected/one-shot-finished are reported explicitly, not confused with a running worker. Successful one-shot never implies production combat safety. Independent offline tests use injected clocks/delays/handlers and TestServer, no real host game actions.

## Verification
Transport tests: expired JWT, concurrent acquisition, read 401 refresh, repeated401, action401/5xx/loss (one POST), rejected/malformed token, bounded transient GET and Retry-After, Basic isolation. Cache tests: isolated temp directory, round-trip, stale/future/invalid/version mismatch, atomic replacement. Runtime tests: default inspect zero actions, one-shot ≤1, unknown read-only reconciliation, invalid config/opt-in/URL zero actions, readiness expiry and drift. Existing complete scenario/replay suites remain mandatory.

Source inspection on 2026-09-06: public OpenAPI 8.2.3; official rate-limit guide documents 429. OpenTelemetry GHSA-88hf-wf7h-7w4m affects Zipkin <=1.15.2 and identifies 1.15.3 as patched. Align compatible telemetry packages as required by NuGet resolution; do not silence the advisory.

## Independent review clarifications
- One shared GET budget permits at most two sends across mixed 401/transient failures. Missing/invalid Retry-After uses a one-second backoff; nonnegative delta/date values up to five seconds are honored; longer delays return the failure without an early retry. A second failure is returned without another refresh/retry. Cancellation during authentication, semaphore/retry wait or before send prevents subsequent dispatch. Staged client operations propagate their token; an already-dispatched ambiguous action is never retried.
- Compatibility matrix: GET `/characters/{name}`, `/maps`, `/resources`, `/items`, `/monsters`; POST `/my/{name}/action/move`, `gathering`, `fight`, `rest`, `equip`, `unequip`, `crafting`. Require CharacterSchema integer level/xp/hp/max_hp/map_id, string name/layer/weapon_slot and array inventory; MapSchema integer map_id, string layer, object access/interactions; CharacterFightDataSchema array characters and object-reference fight/cooldown; SkillDataSchema object-reference character/cooldown/details. Request equipment bodies remain arrays; movement request supports integer map_id. Missing routes/schema/property or incompatible primitive/ref type rejects even with unchanged version. Probe failure/malformed JSON and freshness expiration before dispatch reject.
- Ready is true after successful inspect with Selected/Completed candidates, or a verified one-shot action/completed target, only while probe and observation remain fresh. All-rejected, invalid, cancelled, unresolved/unknown, failed probe and expired state are not ready; liveness remains independent. Invalid modes, missing opt-ins, cross-origin/absolute requests and disallowed origins fail before game actions. Redirects are disabled in production registration.
- Cache identity hashes normalized endpoint and version only, never credentials. Atomic replacement is exercised with concurrent readers and writers; invalid/future/expired/mismatched envelopes are misses.
