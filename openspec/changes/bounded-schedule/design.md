# Design

Schedule.Enabled defaults false. Enabled scheduling requires Inspect startup, enabled observation panel, manual operator controls disabled, existing action permissions, a pure AutonomousGoals gathering profile, and separate LiveSeriesApproved for the official API. The scheduler replaces automatic StagedWorker. Shared execution retains character lease, freshness, durable action intents and no-blind-retry behavior. No schedule is enabled by this change.

Series state lives in RunDirectory/schedule/series.json with its own exclusive lease, initialized marker and flushed atomic replacement, separate from the character checkpoint. Identity pins series ID, origin/character, policy, execution ceilings/freshness/API version and scheduling bounds. Changing IDs/config in the same directory does not reset allowances. Reserve a run's full action/decision/time ceilings before dispatch; never refund unused reservations. Reject a run if its full duration no longer fits the series end date. This is a conservative aggregate ceiling, not measured spending.

One due run per tick; next due time is completion time plus interval. No catch-up queue. An interrupted Running reservation becomes InterventionRequired on restart, even if the run might have finished. Stop is terminal for the series and requests shared cancellation. Unknown/Blocked/Cancelled, foreign or corrupt checkpoint, lease failure, profile mismatch or persistence failure prevent automatic continuation. Successful runs archive only through FileRunCheckpointStore.ArchiveCompleted, with the exact identity digest. A crash between archive and series commit remains intervention-required.

Notifications are stored atomically with series state; at most100 retained, monotonically increasing stable IDs. GET /operator/schedule projects state and notifications. Existing local/Host/origin/control-token guards protect POST /operator/schedule/stop. The panel replaces the notification list by ID-preserving persisted content on polling, rather than appending duplicates. No third-party notification service or browser permission is requested.
