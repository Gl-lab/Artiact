# Design

## Durable state
Autonomous checkpoints use Version=2 and an Autonomous state carrying Algorithm=discovery-v1, active GoalDiscoveryEvidence with its world fingerprint, and at most 128 transitions (Completed/Rejected plus observation fingerprint). A changed catalog/world rejects the old active milestone before generation; an unresolved POST still takes precedence and fails closed on world mismatch. Manual checkpoints stay version 1 and preserve current behavior. No automatic migration between modes/versions. Stable policy Identity includes the algorithm version for autonomous profiles. Generated skills never enter that identity.

StrategyRunContext carries the current active goal and remaining action/time estimates for discovery. Pending reconstruction uses the saved baseline context and active goal; restore must not replace it with freshly discovered state. Selection is saved before preflight/intent. A completed milestone is recorded after authoritative observation, then discovery runs again within the same counters. Ordinary XP changes cannot change its target. Confirmed infeasibility records a rejection and suppresses the same skill/target within the run. Generation does not reset no-progress. History exhaustion terminates with InterventionRequired rather than discarding attribution.

## Stops and archive
Add StrategyStatus.Stopped (at the end of the enum, preserving serialized existing numeric values), with AutonomousBudgetExhausted and NoUsefulSupportedGoals. Budget exhaustion includes actions/decisions/time and a remaining budget too small for the estimated useful path; no-progress remains Blocked. NoUsefulSupportedGoals requires all four skill observations at their supported caps and valid character/catalog observation; unavailable paths and invalid observations remain Blocked. A partial active milestone remains visible on budget stop. Stopped is terminal across restart.

Archive version 2 only for these exact Stopped reasons, valid autonomous version/state, valid initial/latest observations, no pending candidate/command, matching counters, and entirely Verified/Reconciled consumed journal. Zero-action no-goal runs may archive after their valid observation. A budget stop before initial observation cannot archive. Arbitrary Blocked/Cancelled/unknown and corrupt versions remain rejected without changing bytes. Existing version-1 completion gate remains intact. Save must prohibit archived RunId reuse even if policy or limits change; manual historical identities without structured RunId retain exact-identity protection.

run-result exposes autonomous state and identifies Stopped as a normal terminal. The operator explicitly archives and supplies a fresh RunId; the worker never archives or restarts itself. Wall-clock deadline handling must produce a budget stop on a normal elapsed deadline, while explicit cancellation remains Cancelled.

## Quality and failure evidence
Keep R11 utility unchanged. Extend the preregistered protocol with exact synthetic HTTP fixtures and outcome ceilings before running comparisons. Test repeated in-process factory reconstruction, pending response loss, persistence failures on selection/transition, archive refusal and reuse, no-goal zero-action runs and original manual checkpoints. Process recovery includes the same pre/post-acceptance boundaries used by R6, extended for autonomous configuration.
