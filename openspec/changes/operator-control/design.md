# Design

An application coordinator serializes Inspect/start/stop/archive, stores at most 64 expiring Inspect receipts and owns one background task. Scoped execution delegates to the existing StagedExecution with copied execution settings; the HTTP connection does not own its cancellation. Host shutdown requests stop and awaits completion. Repeated start with the same receipt returns the existing acceptance; different starts while busy are rejected. Across restart the same identity/RunId/limits use the existing durable checkpoint, preserving pending reconciliation and budgets. A fresh Inspect is required after host restart; the receipt itself grants no game permissions.

The server portfolio remains configured in existing settings, and the UI prepares RunId and limits within server ceilings. Expose a projected permission summary, never secrets or arbitrary config. Noncombat-only control fails closed on combat profiles. Before accepting start, validate action opt-ins and checkpoint compatibility/ownership; the production executor independently reacquires the lease and rechecks preflight. Blocked/cancelled/unknown archives remain refused by the shared store.

All operator POSTs require an unpredictable per-process CSRF header acquired through same-origin GET. Per the 2026-09-08 trusted-network deployment decision, operator routes accept server addresses and remote clients without login; the network perimeter controls reachability. Cross-origin Origin and Fetch-Metadata requests are refused; no CORS headers are added. The legacy /operation/stop route receives the same browser-origin restrictions. No GET starts, resumes or stops a run. A refreshed page cannot repeat a start; explicit same-run recovery prepares the existing ID/limits for Inspect.
