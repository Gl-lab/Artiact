# Explicit strategy portfolio

`StrategySessionFactory.Create(PortfolioPolicy, StrategyLimits)` builds an explicit session. Registration alone performs no game actions. Default worker and existing mining/loot/craft entry points remain compatibility paths: the portfolio does not claim full legacy parity and they have not been removed.

The immutable policy supplies skill descriptors, combat milestone, opponent, owned weapon target, useful values and estimated action/travel/recovery seconds. Mining and woodcutting use the same `GatheringStrategy`; the coordinator has no profession or goal-type switch. Estimates are configurable assumptions, not measured live XP/hour. Positive bounded values and unique profession IDs are required. `StrategyCandidate` exposes category, value, time components, nullable score and rejection reason. Feasible candidates rank by value / full-cycle seconds, then ordinal ID. Equipment uses separate unequip/equip commands and exact stock conservation; combat uses Epic 6's conservative supported predictor. Gathering currently requires one guaranteed catalog drop with bounded positive quantities.

Each normal tick reads relevant raw catalogs and character state, builds a canonical SHA-256 fingerprint over character/catalog/policy, selects one command and rereads immediately before POST. A changed fingerprint returns Replan with zero mutation. Successful responses are saved before validation/cancellation; the next tick plans again from observed state. A session serializes ticks and consumes each source-fingerprint/command pair once. This does not eliminate external races between GET and POST.

Unknown dispatch outcomes preserve the command and pre-dispatch baseline. The next tick performs only a read-only reconciliation, including when the mutation budget was just exhausted. A valid baseline-relative postcondition returns Reconciled, consuming the command without refunding attempts. Unchanged, unrelated, invalid or changed-catalog state stays terminal UnknownOutcome. Reconciliation establishes desired state, not causation. A later tick must observe an expired cooldown before dispatch. Cancellation before dispatch sends nothing; cancellation after reply saves the response then stops. Defeat, rejected actions, malformed postconditions and cooldown failures are terminal.

All goals satisfied returns Completed. Unfinished but wholly infeasible goals return Blocked with candidate reasons. Every active tick consumes a decision; stale checks and attempts increment no-progress, while verified productive skill/combat/equipment progress resets it. Movement/recovery do not reset it. A final pending reconciliation may consume one additional read-only tick beyond the decision limit; it never grants another action. Default bounds are 100 decisions and 10 no-progress ticks. A future cooldown returns CoolingDown; consumers must schedule later checks rather than busy-looping.

## Deterministic HTTP acceptance

Reset `strategy-portfolio`, load `researcher`. The authored scenario adds mine map 4 and forest map 5 to the combat-equipment starting state. Each gathering yields one ore/wood and five skill XP in five virtual seconds. Values equipment/mining/woodcutting/combat = 100/30/20/10; costs equipment 3, move 7, gather 5, fight 8, recovery 6. Initial category scores are equipment 100/6, mining 30/12, woodcutting 20/12 and combat 10/21.

Expected commands: Unequip, Equip, Move(4), Gather, Gather, Move(5), Gather, Gather, Move(2), Fight, Rest, Fight, Completed. Twelve actions, thirteen decisions, 69 seconds; combat/mining/woodcutting level 2, XP 0, HP 14, map 2, quick_blade equipped. Inventory contains heavy_blade and old each 1, ore/wood/feather each 2; two free units remain. Complete independent response oracles and exact replay protect this contract. Policy variants select each feasible category and reach its productive action; old-weapon combat is scripted as four turns, final HP 8, five XP and one feather, not a live damage claim.

`StrategySessionTests` covers coordinator boundaries; `StrategyPortfolioFlowTests` uses real clients over TestServer, including lost replies, cancellation and corrupted responses for equipment, gathering and combat. Existing mining/combat/craft suites remain regression gates. Live rollout remains unverified; see ADR 0001 and Epic 8 operational work.
