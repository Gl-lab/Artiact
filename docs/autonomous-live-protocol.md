# Separate autonomous live acceptance protocol

Status: prepared on 2026-09-08; **game-action acceptance not executed or authorized by the offline roadmap work**. A separate read-only autonomous preflight on 2026-09-08 returned AutonomousBudgetExhausted with zero attempts; see [R19 preparation evidence](../openspec/changes/operator-live-acceptance/verification.md). Previous manually scoped mining/movement authorizations do not authorize this new autonomous run. CombatDiscovery remains outside this protocol under ADR0001.

Before any game action, record the exact reviewed commit, official HTTPS origin, one character, current character/catalog fingerprints, policy identity, fresh Inspect result, proposed first command, stock floor and limits. Use current observations, not tracked reference caches. Inspect must contain no game POST. The origin remains `https://api.artifactsmmo.com`; do not transmit credentials elsewhere or include credentials/payloads in evidence.

The first action scope is a supported gathering-only autonomous profile: empty manual goals, AutonomousGoals true, Recovery/CombatDiscovery absent and bank disabled. Require enough observed inventory for the bounded path. Proposed ceilings are MaxActions2, MaxDecisions6, MaxNoProgress3, MaxSeconds120; lower them if the concrete inspected route requires less. Stop if these bounds make the route infeasible. Do not expand bounds, add categories or switch characters to obtain a passing result.

Prepare an exact named-character/command allowlist from Inspect, a new stable RunId and dedicated absolute run directory outside Git. A new explicit approval must cover that concrete scope before Bounded/AllowActions is enabled. If autonomous replanning selects a command outside the approved allowlist, the transport must reject it. Existing origin/action consent, OpenAPI/freshness checks, exclusive character lease, flushed intent and no-blind-retry HTTP behavior all remain required. Do not use unguarded host startup as the acceptance command.

Run at most the approved bounded scope; never clear a checkpoint to rerun it. Stop on contract drift, stale state, inaccessible route, invalid postcondition, cancellation, resource limit or unknown result. After an uncertain POST, retain the intent and use only read-only reconciliation. A changed catalog during ambiguity cannot authorize another action. Process termination before POST may still require intervention because unchanged state does not prove non-dispatch.

After stopping, use the existing offline `run-result` command with the exact origin/character identity. Record actual attempts, verified/reconciled/unknown entries, confirmed cooldown (missing remains missing), per-skill level/XP, preserved inventory and terminal reason. Reopen the same run and verify that limits/terminal state survive without another POST. Archive only if the existing verified lifecycle rules allow it, then start any subsequent run with a separately approved new RunId. Unknown/Blocked/Cancelled checkpoints are not disposable.

Passing this protocol would establish only that named noncombat slice on its observed API revision. HP production and combat need separate concrete protocols; combat additionally needs the matched compatibility evidence required by [ADR0001](decisions/0001-combat-viability-and-recovery.md). Offline comparison wins and synthetic cooldown do not substitute for that evidence. Scheduling, 24/7 execution and remote hosting remain outside scope.
