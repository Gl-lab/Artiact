# Ограниченные серии и уведомления — R20

Расписание явно включает последовательные автономные запуски добычи. По умолчанию `Schedule:Enabled=false`. Каждый запуск использует общий `StagedExecution`: свежие наблюдения, владение персонажем, журнал намерений, лимиты и запрет повторять неопределённый POST сохраняются.

## Настройка

Необходимы `Execution:Mode=Inspect`, `Operator:Enabled=true`, `Operator:ControlsEnabled=false`, `Portfolio:AutonomousGoals=true` и постоянный `Execution:RunDirectory`. Ручные цели, бой, банк, восстановление, расходники и подготовка в серии не поддерживаются. Обычные разрешения `Execution:AllowActions` и, для официального API, `Execution:LiveActionsApproved` остаются обязательными. Для официального API дополнительно требуется `Schedule:LiveSeriesApproved=true`, выставленный после отдельного согласования всей серии. Разрешение прежнего R19-прогона этого не покрывает.

| Ключ Schedule | Значение и предел |
|---|---|
| `Enabled` | По умолчанию false; true регистрирует ScheduleWorker вместо обычного worker |
| `SeriesId` | 1–60 латинских букв/цифр, `_` или `-`; первый символ — буква/цифра |
| `FirstRunUtc`, `ExpiresUtc` | Явные даты начала и конца; окно положительное, не длиннее 31 дня |
| `IntervalSeconds` | 1–86400, по умолчанию 60; отсчитывается от окончания предыдущего запуска |
| `MaxRuns` | 1–10000 |
| `MaxTotalActions` | 1–1000000 |
| `MaxTotalDecisions` | 1–2000000 |
| `MaxTotalSeconds` | 1–2678400 |
| `LiveSeriesApproved` | По умолчанию false; отдельное разрешение серии для официального API |

Пределы одного запуска задаются существующими `Execution:MaxActions`, `MaxDecisions`, `MaxNoProgress`, `MaxSeconds`; freshness и версия API также сохраняются. Неполная/невалидная конфигурация не допускает исполнения. Настройки фиксируются при запуске хоста; изменение файла не является командой остановки. Используйте кнопку «Остановить серию» или штатное завершение хоста. Для отключения следующих запусков хоста установите `Schedule:Enabled=false`.

## Бюджет и восстановление

До передачи управления исполнителю сохраняются статус Running и **полные потолки** действий, решений и секунд очередного запуска. Остаток не возвращается. Например, два запуска с потолком 6 действий резервируют 12, даже если фактически выполнили по 4. Фактические расходы остаются в журналах отдельных запусков. Новый RunId (`SeriesId-0001`, `SeriesId-0002`, …) не обнуляет общие счётчики.

Следующий запуск возможен только когда его полный бюджет помещается в остаток серии, а `now + MaxSeconds` не выходит за ExpiresUtc. Проверка времени повторяется после Inspect. Пропущенные интервалы дают один запуск, без очереди наверстывания. Дедлайн не обещает мгновенное прерывание уже отправленного запроса: действуют существующие правила подтверждения результата и остановки.

`RunDirectory/schedule/series.json` содержит закреплённую идентичность профиля/персонажа/лимитов, счётчики и события. `series.lock` исключает одновременное изменение серии; запись идёт через flushed temporary file и атомарную замену. Маркер `initialized` предотвращает незаметное создание новой серии при потере файла. Смена SeriesId или лимитов в том же каталоге отклоняется. Не удаляйте состояние для обхода бюджета; следующая согласованная серия требует отдельного каталога с сохранением предыдущих материалов.

Перед Inspect проверяется отсутствие активного checkpoint и доступность существующей character lease. Исполнитель повторно получает lease перед действием. Только штатный Stopped с AutonomousBudgetExhausted/NoUsefulSupportedGoals и проверенным безопасным журналом допускает штатное архивирование. UnknownOutcome, Blocked, Cancelled, чужой/повреждённый checkpoint, занятое владение либо ошибка архивирования останавливают серию для вмешательства. Сохранённый Running при перезапуске также требует вмешательства: даже потенциально успешный прерванный запуск автоматически не повторяется. Остановка сохраняет зарезервированный бюджет.

Используйте один согласованный каталог владения для персонажа; локальные файловые блокировки не координируют независимые каталоги, машины и внешние игровые клиенты. Непрерывная работа 24/7 и live-приёмка расписания в R20 не заявляются.

## Панель и уведомления

`GET /operator/schedule` показывает серию, резерв/пределы и последние 100 событий; `POST /operator/schedule/stop` запрашивает остановку. Действуют общие loopback/Host, Origin и `X-Artiact-Control` проверки. Ручной Start при включённом расписании недоступен. Закрытие страницы не останавливает серию.

Завершение запуска/серии, отказ и необходимость вмешательства сохраняются вместе с состоянием. ID монотонны внутри SeriesId и сохраняются при перезапуске. Повторный опрос заменяет список только при изменении состояния, не добавляет копии событий. Канал — локальная панель; email, чат и системные push не отправляются. Если само хранилище недоступно, панель показывает InterventionRequired/ScheduleStorageOrConfigurationInvalid; сохранённая доставка уведомления в этом случае не гарантируется.

Проверки и непроверенные границы: [R20 evidence](../openspec/changes/bounded-schedule/verification.md).
